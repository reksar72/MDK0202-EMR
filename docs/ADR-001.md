# ADR-001 — SQLite и разделение ядра от адаптеров
Статус: принято для учебного стенда. Дата: 05.11.2026.

## Контекст
Нужно повторяемо запускать импортер, API и тесты без отдельного сервера базы. При этом правила сопоставления и доступа не должны зависеть от способа хранения.

## Решение
Использовать .NET 8/C#, интерфейс IPatientRepository в AIS.Core и SQLite-адаптер в AIS.Infrastructure. Внешний контракт фиксировать OpenAPI 3.0.3. WPF-клиент связывает View и ViewModel через Binding/INotifyPropertyChanged; HttpClient скрыт за IMedicalApiClient.

## Рассмотренные альтернативы
Хранение только в памяти упрощает запуск, но не проверяет сохранение и ограничения уникальности. PostgreSQL лучше подходит для многопользовательского сервера, но требует отдельной установки. Для этого задания выбрана SQLite.

## Последствия
Плюсы: автономный запуск, транзакции, проверяемые коллизии, замена хранилища через интерфейс. Минусы: SQLite не выбирается автоматически для общей промышленной медицинской системы; нужны оценка нагрузки и отдельный план внедрения. Для реальных данных необходимы доверенный IdP, TLS, управляемое хранение ключей и согласованная политика доступа. В текущем стенде используются только синтетические записи.
