# Требования к учебной АИС ЭМК

Вариант 2 из сборника МДК 02.02. Данные полностью вымышленные.

UC-01: врач получает краткую карту назначенного пациента. Предусловия: действующий токен, роль Doctor, назначение на карту. Результат: только summary и запись шифрованного аудита; иначе 401/403/404.
UC-02: медсестра проверяет доступ с целью NursingCare. Цель Treatment ей не разрешена. При ошибке запроса — 400; журнал фиксирует решение.
UC-03: администратор задаёт роли и назначения при подготовке контура. Административная роль сама по себе не даёт права читать медицинскую карту. В учебном запуске состав акторов задаётся в composition root; редактор аккаунтов не входит в программу.

FR-01: сопоставление реестровой карточки с внутренним Patient по явному UUID.
FR-02: даты dd.MM.yyyy → DateOnly; UpdatedAt → UTC; полис — строка из 16 цифр.
FR-03: повтор импорта не создаёт дубль; устаревшая версия не перезаписывает новую; конфликт версии отклоняется.
FR-04: GET /api/v1/patients/{id}/summary и POST /api/v1/access/check.
FR-05: роль и ID сотрудника определяются сервером по Bearer-токену.
FR-06: аудит шифруется AES-256-GCM; ключ не входит в исходники.
FR-07: MVVM-клиент не содержит SQL и HTTP-вызовов в ViewModel.
NFR-01: Core не зависит от UI и Infrastructure; граф ProjectReference не имеет циклов.
NFR-02: SQL использует параметры; ошибки UI очищают прежние данные и завершают состояние IsBusy.
NFR-03: локальный HTTP разрешён только для учебного loopback-сервера; внешний клиент требует HTTPS.
